# VVPhmi 超棒(๑•̀ㅂ•́)و✧的上位机！

面向**电气行业**的开源调试与监视软件：多协议采集 + 参数表驱动 + 实时监视 +
**录波示波器** + 主回路**示意图** + 历史/报警/报文诊断 + **一套可扩展的现场小工具**。

以 **SST（固态变压器）** 工程为例：`10kV 电网 → 级联整流 → 直流母线 → DC/DC → 800V 直流输出`，
三块 DSP 各为一个 Modbus 从站，点击示意图上的设备即可进入该 DSP 的详情页。

当前版本 **1.0.0**（Windows 11 x64 免安装 exe，见 [第十七节](#十七打包为免安装程序)）。
更新内容见 [CHANGELOG.md](CHANGELOG.md)。

> 目录名与 Python 包名仍是 `icomm`（改了会破坏已有部署目录与全部 import），
> 界面标题、窗口标题、打包产物用的是 **VVPhmi**。

## 软件放哪儿、工程放哪儿

**软件目录里只放软件**（源码 / 打包产物 / 测试 / 文档 / 图标）；
**工程另存一处**，统一放进一个叫 **`VVPproject`** 的工程仓库，一个工程一个文件夹。

**磁盘上的目录名一律英文**（`config` / `data` / `reports`）——
中文目录名在命令行、ZIP、同事的英文系统上都容易出乱码；
界面里显示的**工程名照旧用中文**（比如「SST 固态变压器」）。

```
VVPproject/                             ← 工程仓库（软件目录外面）
  sst-transformer/                     文件夹名英文（工程名还是中文）
    config/                            工程配置（可交付、可进版本库）
      project.json                     通道 / 设备 / 点位 / 示意图 / 存储设置
      parameters.csv                   参数表，Excel 可直接打开改
      diagram.svg                      可选：示意图底图
    data/                              运行与测试数据
      history.db                       历史 + 报警 + 通信日志 + 录波
    reports/                           导出的测试结果（跟配置分开）
      datalog/  faults/  shots/  audio/
  bess-storage/                        储能电站示例
  pv-plant/                            光伏电站示例
  power-grid/                          电力系统（配电网）示例
  cabinet-monitor/                     配电柜示例
  _opened/                             打开 .iprj 时解压到这里（系统用）
  _archive/                            跑测试留下的数据（系统用）
```

内置示例的文件夹名固定为 `bess-storage` / `pv-plant` / `power-grid` / `sst-transformer` / `cabinet-monitor`。
自己新建的工程按工程名自动生成英文名（纯中文名会生成 `project-1` 这种），
也可以在「设置 → 工程设置 → 文件夹名」里手填，点确定后就地改名。
老工程里的中文目录（`配置`/`数据`/`报表`）仍然认，打开时会自动改成英文。

**仓库位置不用手填**：启动时按下面的顺序自己找，找到就用，都没有才在软件目录**旁边**新建。

1. 环境变量 `VVPHMI_PROJECT_HOME`
2. 「设置 → 软件设置 → 工程存放位置」里指定的目录
3. 从软件目录**向外**逐级找现成的 `VVPproject`（最多 4 层）
4. 软件目录自己（便携式布置）→ 当前工作目录同上
5. 「文档」目录 / 用户主目录下的 `VVPproject`

这样源码运行（仓库在 `VSCodeWorkspace`）与打包运行（exe 在 `dist/VVPhmi/`）会指向**同一个**工程仓库。

## 一、功能总览

### 已实现

| 分类 | 内容 |
|---|---|
| 组态模型 | 通道 → 设备 → 点位 三级结构；一条通道（一个 TCP 连接或一个串口）挂多台从站 |
| 协议驱动 | **插件化**：新增协议只加一个文件，界面自动生成连接参数表单。已内置 Modbus TCP / RTU / RTU over TCP |
| 点位类型 | **标量**（普通遥测遥控）与 **数组/块点位**（一次读回整段波形，用于录波） |
| 状态字/控制字 | 点位可配**位定义**（界面按位置显示状态名，如「就绪 / 运行」）与**命令按钮**（点一下就写命令码，如启动/停机/复位） |
| 点位操作 | 任意点位**双击**打开参数对话框改值；**右键**单发写入 / 持续发送 / 添加到示波器 / 调出按键小窗口 / 编辑点位定义 |
| 持续发送 | 周期性写同一个值，带发包计数与失败统计；配置随工程保存，但**打开工程时不会自动开始** |
| 按键控制台 | **非模态浮动小窗口**（可同时开多个），按键全部来自参数表；设备级控制台自动收集命令点位 |
| 保存与导出 | 拆成「保存参数设置」与「保存整个工程」，**格式可选**：CSV / TXT / JSON、工程目录 / `.iprj` |
| 界面自定义 | 4 套预设主题 + 字体 + 字号 + 界面密度，另可**逐项自定义每一个颜色**，改动实时预览 |
| 设置 | 四页：界面外观 / **通信（全部通道的 TCP·RTU 参数，可新建删除）** / 软件设置 / 工程设置 |
| 工具集 | **可插拔**的「工具」菜单：变量搜索、记事本、截屏辅助、数据记录、故障录波、录音、计时器与定时赋值、示波器小窗口、主回路图编辑、分析工具、程序员计算器、Modbus 报文与 CRC、TCP 连接测试。加工具 = 新建一个文件 + 一行 import |
| 自动化 | 统一的「**满足条件就做点什么**」核心：截屏 / 数据记录 / 故障录波 / 录音 / 定时赋值共用同一套触发判断（电平、上升沿、下降沿、8 种比较、去抖、冷却、次数上限） |
| 故障录波 | 一直往回记（环形缓冲），报警或自选变量一触发就留下**触发前后**各一段（默认各 1s，可改）；存进录波表，可用示波器录波回放看，也可导出 CSV |
| 录音 | 用系统自带 winmm（**不加任何依赖**）录音，同样由变量触发、录够时长自动停，WAV 存盘并可列表播放 |
| 主回路图编辑 | 工具里直接编主页那张图：**20 个电气图元**（电网/电池/光伏/开关/变压器/滤波/整流/逆变/DC-DC/母线/负载/电动机/仪表/DSP…）、拖动摆位、连线（交流/直流/信号）、绑定实时值、设点击跳转，可导出/导入 JSON |
| 分析工具 | 四个页签：**滤波器伯德图**（R/L/C → 幅频相频、谐振点、-3dB）、**锁相**（从波形算频率与相位角）、**功率因数/功率角**（含无功与趋势）、**三相向量**（正序/负序/零序分解与不平衡度） |
| 时间 | 状态栏常驻时钟；工具里有秒表（开始/暂停/清零/打时刻标记）与定时赋值 |
| 写值安全 | 任意点位可设**写值限幅**（单发与持续发送两条路径都夹紧并留日志），限幅随工程保存进参数表 |
| 界面微调 | 任意点位可设**显示小数位数**（只影响显示，不动设备里的值） |
| 配色文件 | 外观（42 项颜色 + 字体 + 字号 + 密度）可**导出/导入 JSON**，方便发给同事或备份 |
| 程序图标 | 自带科技感图标（`assets/icon.ico`，含 16~256px 七个尺寸），窗口与 exe 都用它 |
| 数据类型 | bool / uint16 / int16 / uint32 / int32 / float32 / float64；两种字序；缩放+偏移，读写双向可逆 |
| 参数表 | **CSV 参数表**定义全部点位（地址/类型/字序/缩放/报警/位定义/命令…），可用 Excel 直接编辑后导回 |
| 采集 | 每通道一线程，设备独立采集周期；批量合并读；数组点位自动分块（>125 寄存器）；失败重试与断线重连 |
| 报警 | 高高限/高限/低限/低低限 + 三级级别，回限自动复位 |
| 存储 | SQLite（WAL）归档历史、报警、通信日志、**录波片段**；写入走独立线程，定时提交 |

| 示波器 | **录波模式**（触发/时基/双光标测量）与**趋势模式**；录波入库后可回放与导出 CSV |
| 其他页面 | 运行监视（变量配置即出画面）、历史趋势、报警记录、通信监视（原始报文）、设备与点位配置、设备详情 |
| 工程管理 | **工程目录模式** / **松散模式**（库与参数表路径各自指定）/ **`.iprj` 单文件工程包** |
| 链路切换 | 通道的 **RTU 与 TCP 参数各记一套**，来回切换不用重填串口号/端口号；两套都存进工程 |

| 内置示例 | **储能电站（BESS）**、**光伏电站（PV）**、**电力系统（配电网）**、SST 固态变压器、配电柜监控。示例参数表在 [examples/](examples/)，一个示例一个模块（[icomm/core/samples/](icomm/core/samples/)） |

## 二、快速开始

```bash
pip install -r requirements.txt

# 直接运行：首次会按软件设置里的示例（默认储能电站）建工程并打开
python main.py

# 演示模式：同时拉起内置仿真器并自动开始采集，开箱即见数据与波形
python main.py --sim

# 指定示例（内置五个：储能 / 光伏 / 电力系统 / SST / 配电柜）
python main.py --sample "光伏电站（PV）" --sim

# 打开指定工程（工程包 / 工程文件 / 工程目录都行）
python main.py --project 现场工程.iprj
python main.py --project D:/项目/project.json

# 覆盖历史库路径（设为自定义路径即"松散模式"）
python main.py --db Z:/plant/history.db
```

启动后建议顺序：工具栏 **「启动内置仿真器」** → **「启动采集」** → 主页看示意图 →
点图上高亮的方框（储能示例是「PCS 储能变流器」，光伏示例是「组串式逆变器」）进入设备详情 →
左侧「示波器」看波形。

三个示例都能演示控制链路：

* **储能（默认）**：「运行监视」页点控制字卡片上的 **「开机」**，状态字变 `就绪 / 运行`、
  有功功率跟着充放曲线走，点 **「关机」** 回落；
* **光伏**：控制字 `0x01 开机` / `0x02 关机` / `0x08 限功率` / `0x04 复位`，
  并网点有功在 0 与额定 500 kW 之间变化；组件温度每天先越 60℃ 告警、再越 70℃ 过热停机；
* **电力系统（配电网）**：遥控命令字 `0x01 合闸` / `0x02 分闸`，
  进线电流、功率与断路器位置一起变。

（各示例详见 [第六节](#六内置示例工程)）

想看写值相关的功能：在运行监视页**双击**「有功功率给定」卡片改值并单发，
或**右键**它选「持续发送」（会先弹一次确认），并网点有功会跟着给定走；
右键里还有「添加到示波器」（任意点位都能加）与「调出按键控制小窗口」。
做法见 [第十节](#十按键控制小窗口) 与 [第十一节](#十一点位操作双击改参数右键单发--持续发送)。

想看工具与自动化：工具栏「工具」菜单里逐个打开试试，
把「截屏辅助」的条件设成 `AB线电压 ≥ 0`、点「添加任务」，十几秒后目录里就会出现现场截图；
「数据记录」勾几个量、起始方式选「变量触发开始」也能自动开记。
见 [第十二节](#十二工具集) 与 [第十三节](#十三自动化满足条件就做点什么)。

> 写值前建议先给点位设**写值限幅**（右键「写值限幅…」）：
> 手滑把 700 打成 70000 时，引擎会先夹到边界再下发，并留一条日志。见 [第十四节](#十四写值限幅与显示小数位数)。

想调界面：工具栏「设置」→「界面外观」，换主题/字号/密度会**立刻看到效果**，
「高级」页还能逐项改每一个颜色；「通信」页集中管所有通道的 TCP / RTU 参数。
见 [第八节](#八设置)。

## 三、参数表（CSV）

**参数表是点位的唯一来源**，可以用 Excel 直接编辑，也可以另存为 TXT / JSON
（见 [第九节 保存与导出](#九保存与导出)）。

- 工具栏「新建 / 示例」→「载入示例：SST 固态变压器」先跑起来；
- 设备与点位页 → **「参数表：生成模板」** 会导出一份带 SST 示例行的模板，照着改；
- **「参数表：导出 CSV」** 导出当前工程；**「参数表：导入 CSV」** 读回来。

文件写为 **UTF-8 with BOM**，Excel 打开中文不会乱码。

### 列说明

| 列 | 含义 | 示例 |
|---|---|---|
| 启用 | 该行是否生效 | 是 |
| 通道 | 所属通道名，留空则用工程里第一个通道（没有就自动建「通道1」） | SST控制链 |
| 设备 | 设备名，不存在会自动创建 | 级联整流DSP |
| 从站号 | Modbus unit id | 11 |
| 点号 | 点位的英文标识，设备内唯一 | A相电压 |
| 显示名称 | 界面上显示的中文名 | A相电压 |
| 分组 | 运行监视页的分组标题 | 三相电压 |
| 寄存器区 | `coil` / `discrete` / `holding` / `input` | holding |
| 起始地址 | **从 0 开始**的偏移（手册上的 40001 对应 0） | 0 |
| 类型 | `uint16` / `int16` / `uint32` / `int32` / `float32` / `float64` / `bool` | float32 |
| 元素个数 | 1 = 标量；**大于 1 = 数组/块点位（录波用）** | 1 |
| 字序 | 32/64 位数据的字序：`big`（高字在前，默认）/ `little` | big |
| 缩放 / 偏移 | 工程量 = 原始值 × 缩放 + 偏移 | 1 / 0 |
| 单位 / 小数位 | 显示用 | V / 1 |
| 可写 | 允许写入（界面上出现写值入口） | 否 |
| 写值下限 / 写值上限 | **写值限幅**：超出范围的值会被夹到边界再下发，**留空表示那一侧不限** | 0 / 800 |
| 限幅提示 | 被夹紧时是否写一条日志说明 | 是 |
| 归档 / 死区 | 是否记历史、变化多少才记一条 | 是 / 0 |
| 显示方式 | `none` / `card` / `gauge` / `lamp` / `wave` | card |
| 仪表下限 / 上限 | 显示方式为 gauge 时的量程 | 0 / 300 |
| 录波 | 数组点位是否把整段波形写入数据库 | 否 |
| 采样间隔us | 数组点位相邻采样点的时间间隔（微秒），决定示波器时间轴 | 0 |
| 示波器 | 是否默认出现在示波器通道列表（数组点位留空即默认是） | 是 |
| 位定义 | **状态字/控制字的位含义**，`序号:位名` 用逗号或分号分隔 | `0:INIT,1:自检,5:运行` |
| 命令 | **控制字的命令按钮**，`值:按钮名`，值支持十进制与 `0x` 十六进制 | `0x04:停机,0x20:启动,0x80:复位` |
| 报警级别 | `info` / `warning` / `critical`，留空则不启用报警 | warning |
| 高高限/高限/低限/低低限 | 四限值，**留空表示不启用该限值** | 250 / 240 / 198 / 190 |
| 备注 | 说明文字 | A相电压 |

### 状态字与控制字（位定义 / 命令）

PCS、逆变器这类设备的「运行状态字」和「控制字」本质是**位掩码**，直接显示数字没人看得懂。
给点位填上 `位定义` 和 `命令` 两列，界面就会自动变成能读、能点的样子：

```csv
设备,从站号,点号,显示名称,分组,起始地址,类型,可写,位定义,命令
储能变流器PCS,31,运行状态字,运行状态字,状态与控制,14,uint16,否,"0:停机,1:待机,2:充电,3:放电,4:故障,5:维护",
储能变流器PCS,31,控制字,控制字,状态与控制,17,uint16,是,,"0x01:开机,0x02:关机,0x04:充电,0x08:放电,0x10:复位"
```

板卡上的表现（以本项目的储能示例为例）：

- **标题**显示当前置位的状态名，多个位同时置位就一起显示：`就绪 / 运行`；
- **下方一行**是完整状态图，置位的位名高亮、未置位的暗显；位名太多时会自动只列置位的并用 `+N` 收口，
  完整明细在**鼠标悬停提示**里；
- **填了 `命令` 的点位**在卡片上渲染成按钮组，点一下就把对应值写下去（走引擎的写值队列，与手动写值同一条路径）；
- 中文位名太长、卡片又窄时会自动降字号；连最小字号都放不下时退化为 `15 / 27 置位` 计数，
  **不会出现被裁掉一半的文字**。

位序号会自动按数据类型裁剪（`uint16` 只认 bit0..15，`uint32` 只认 bit0..31），写错的位序号直接忽略。

### 导入行为

- 逐行校验，问题按「第 N 行 + 原因」汇总弹出，**一行写错不会导致整份失败**；
- 两种模式：**更新/新增**（保留表里没有的点位）与**清空重建**；
- 布尔列兼容 `是/否`、`1/0`、`true/false`、`Y/N`；整数列兼容 Excel 写出的 `10.0`；
- 保存工程时若发现**参数表被外部改过**（你用 Excel 改了但没导入），会先问你：
  覆盖它、还是保留它等着导入 —— 避免辛苦改的内容被无声覆盖。

## 五、示波器与录波

### 为什么用"数组/块点位"

要画**真实的三相 50Hz 正弦**，靠标量点位逐点轮询是做不到的：Modbus RTU 一个来回几十毫秒，
按 200ms 采样去画 50Hz 会严重混叠，画出来好看但完全是错的（采样定理）。

工业上的做法是**录波**：DSP 把一段波形存在自己的缓冲区里，上位机一次性成块读回来再画。

### 怎么接到你的 DSP 上

1. **把波形缓冲区放在一段连续的保持寄存器里**（本示例：`holding 10` 起 200 个寄存器 = A 相电压）。
   这是绝大多数 DSP 的做法，我们直接支持。
2. 在参数表里把该点位配成数组点位：**元素个数 = 200**（示例 `int16`，每点 2 字节）。
3. 填 **采样间隔us**（示例 100，即 10kHz 采样；200 点 × 100us = 20ms，恰好一个工频周期）。
   填了它，示波器的横轴就是真实时间（ms）；不填就按点序号显示。
4. 需要长期留档就勾上 **录波**（数据量大，默认关闭：200 点 float32 ≈ 800 字节/段）。

**若你的 DSP 不是"连续寄存器缓冲区"**（例如要看门信号、或波形走高速通道/UDP、
或需要先写命令字触发录波再读），驱动的读取接口已经预留了扩展位：
在 `icomm/core/drivers/` 里新增驱动类，`read_points` 里自行决定怎么把一段波形取回来即可，
上层的示波器、录波入库、历史回放都不用改。

### 屏幕功能

- **录波模式**：自动按点位类型切换。支持**上升/下降沿触发 + 触发电平**（触发点对齐后波形才稳得住）、
  自动量程或手动量程、**双光标测量 Δt 与 ΔV**（左键放 A 光标、右键放 B 光标、滚轮缩放时基）。
- **趋势模式**：标量点位按"秒/格"滚动，适合看有效值、温度这类低频量。
- **录波历史**：底部列出数据库里录下的每段波形（时间/点号/点数/采样间隔），
  双击载入画布回看，也可导出成 CSV。切到本页会自动刷新。

### 没有波形缓冲区时：按瞬时值看趋势

现场很多设备（尤其是只走 Modbus 读一批保持寄存器的）**没有波形缓冲区**，
能把 A 相电压的**有效值**读回来，但读不回"一段 20ms 的正弦"。
这时示波器页会：

- **不再空着**：一个点位都没标「示波器」时，自动把工程里启用的点位**全列出来**
  （提示里会写明"没有点位标「示波器」，先按全部点位列出"）；
- **按瞬时值画趋势**：每个采集周期取一个点，横轴按"秒/格"滚动。
  提示栏会说明现在是瞬时值模式，并给出**一个点多久来一次**（`约 200 ms/点`）；
- **太稀会提醒**：每格点数不足 4 个时提示 `曲线会很稀 —— 把设备的轮询周期调小，或把时基调大`，
  免得看到一条折线以为软件卡了；
- **录波历史那一栏也会说明**为什么没有波形可回放。

> **想画真实的三相正弦**：还是得让 DSP 提供缓冲区（见上面两节），
> 或者以后按"数组/块点位"方案扩展。瞬时值趋势只能看有效值/温度这类低频量，
> 按 200ms 采样去画 50Hz 会严重混叠 —— 画出来好看但完全是错的（采样定理）。

### 示例是怎么组织的

一个示例一个模块，放在 [icomm/core/samples/](icomm/core/samples/)：

| 文件 | 内容 |
|---|---|
| `bess.py` / `pv.py` / `grid.py` | 一个示例一个模块：点表 + 仿真行为 |
| `_common.py` | 建点位、配报警、画主回路图的共用写法 |
| `_sim.py` | 仿真写寄存器的小助手（保证「工程量 ↔ 原始值」的换算和点表一致） |
| `__init__.py` | 注册表：示例名 → 构造函数，以及从站号 → 示例模块的分派 |

**为什么点表和仿真放同一个文件**：地址或 `scale` 填错会出现「示波器幅值不对」「负值显示成 6553」
这类很难查的问题，所以两者共用一张模块级 `_REG` 表 —— `build()`（建工程）与 `simulate()`（刷数据）
都从那里取，只写一份，不可能两边对不上。

**可写点只在启动时写一次默认值**：每轮的 `simulate()` 只刷只读遥测。
否则主站刚写进去的定值/给定，下一拍就被仿真刷回默认值了。

**仿真的时间刻度**：仿真一个「日」只有 240 s（光伏示例：日出 t=0、日落 t=120，之后入夜），
所有周期都压到秒级，坐着看几分钟就能把「告警 → 故障 → 恢复」走完整。
真实装置按天/小时计。

**加一个自己的示例**：新建 `icomm/core/samples/xxx.py`（照 `bess.py` 抄），
提供 `NAME` / `FOLDER_NAME` / `UNIT`（或 `UNITS`）/ `POLL_INTERVAL_MS` /
`build()` / `simulate(store, t)`，再在 `__init__.py` 的 `MODULES` 里加一行 ——
示例菜单与内置仿真器都会自动带上它，不用改别的地方。

### 示例的主回路图

每个示例都带一张数据驱动的主回路图，图元可点击跳设备详情，也能在图上叠加实时值：

* **储能**：`10kV 电网 → 并网断路器 → 升压变 → PCS 储能变流器 → 直流母线 → 电池簇 ×8`，另带关口计量与消防/温控；
* **光伏**：`光伏组串 ×8 → 汇流箱 → 组串式逆变器 → 升压变 → 并网计量 → 10kV 电网`，另带 MPPT 与逆变控制 DSP；
* **配电网**：`10kV 母线 → 进线断路器 → 馈线 → 配变 TTU → 低压侧负荷`。

### 接到自己的设备上

1. 「设备与点位」页把通道从 `tcp` 改成 `rtu`，填串口号（下拉里会列出本机检测到的串口，也可以手打）
   与波特率/校验位（默认就是现场最常用的 **9600 8E1**）；
2. 从站号改成你装置的实际 unit id；
3. 用 [examples/](examples/) 里最接近的示例参数表当底稿，按你的点表改地址与位定义后导入；
4. 停掉内置仿真器（工具栏再点一次「启动内置仿真器」）即可接真实设备。

> 示例的轮询周期是 **200~500 ms**（各设备的「轮询周期」都能改）。
> 它同时决定示波器趋势模式的密度：轮询越快曲线越顺，但占用的总线时间也越多，现场按设备能力折中。
> 储能与光伏示例**带波形缓冲区**，所以示波器页能画真实波形；
> 没有波形缓冲区的点位只能按**瞬时值**画趋势
> （见「五、示波器与录波 → 没有波形缓冲区时」）。

### 窗口大小

- **记住大小与位置**（默认开）：关窗口时存下来，下次启动还原；换到小屏或拔掉外接显示器时，
  如果记的位置已经落到屏幕外，会自动压回屏幕内；
- **恢复默认大小**：窗口被拉得太大、或者跑到屏幕外面点不到了，用它立刻回到合适大小
  （在「设置 → 软件设置 → 窗口」里，点确定后立即生效，不用重启软件）；
- 窗口最小尺寸由布局决定，当前约 **1000 × 550**，1280×720 的屏也放得下。
  页面里的长说明文字用的是会省略/折行的标签，不会再把窗口顶得比屏幕还宽。

### 界面外观

界面可以简单自定义，分两级：

- **常用**：选配色主题、字体、字号、界面密度。改完**立刻看到效果**（实时预览），
  按「取消」会整页还原，所以可以放心乱调。
- **高级**：按 6 组（背景层次 / 文字 / 强调色 / 控件 / 质量戳 / 报警级别 / 绘图区）
  逐项改**每一个颜色**，每个颜色旁边有对应色块，点一下调色板选色。

内置 6 套预设，**默认是 DeepSeek 那一套**（现场看着清爽，也不刺眼）：

| 主题 | 适用 |
|---|---|
| **DeepSeek 深色（默认）** | 常规使用：纯黑底 + DeepSeek 蓝，取自 DeepSeek 官方界面样式表 |
| DeepSeek 浅色 | 白天强光、投屏、打印截图（白底 + #3964fe 蓝） |
| 深色工业 | 控制室常规照明（绿强调色） |
| 深蓝夜间 | 长时间盯屏，蓝光少一些 |
| 浅色办公 | 浅色办公环境 |
| 高对比现场 | 现场强光/远距离看，全黑底高饱和 |

> DeepSeek 那两套里的关键色是**原值**：深色底 `#000000`、正文 `#f5f5f7`、
> 次级文字 `#adb2b8`、强调色 `#5686fe`、品牌蓝 `#4d6bfe`、成功绿 `#22c55e`、警示橙 `#f97316`；
> 浅色底 `#ffffff`、正文 `#1d1d1f`、次级文字 `#81858c`、强调色 `#3964fe`。
> 面板层次 / 边框 / 网格这些官方样式表里没有的，是在同一色系里补齐的（否则界面分不出层次）。

字号 10~20px、密度「紧凑/标准/宽松」（紧凑适合小屏多塞内容，宽松适合触摸屏）。
绘图区（示波器画布、示意图画布、连线、指示灯、网格）的颜色也跟随主题，
所以浅色主题下示意图不会还是一片深色。

**扩展方式**：加一套预设主题 = 在 `icomm/ui/theme.py` 的 `PRESETS` 里加一个
`Palette`；给主题加一个可调项 = 给 `Palette` 加字段并在 `build_stylesheet` 里用上，
设置界面的「高级」页会**自动**多出对应颜色按钮。

### 通信（Modbus / TCP / RTU）

通道的连接参数在**两处**都能改：「设备与点位」页（选中通道）与设置的「通信」页。
两处指向同一批通道对象，所以改哪边都一致。

- 参数表单完全由驱动的 `option_schema` 生成 —— 加一种协议或给 Modbus 加参数，这里自动就有输入框；
- **串口（RTU）**：串口号是**可下拉也可手打**的输入框 —— 点开下拉会**重新扫描**本机串口
  （USB 转串口插拔很频繁），而手打的、或设备没插但工程里配好的串口号**不会被重扫冲掉**
  （下拉项里会标注"系统当前没枚举到这个串口，仍按填写值使用"）。
  默认参数是现场最常用的 **9600 8E1（波特率 9600 / 8 数据位 / 偶校验 / 1 停止位）**，
  波特率与校验位都能改，校验位在界面上显示成中文（无校验 / 偶校验 / 奇校验）；
- **TCP 与 RTU 的参数各记一套**：切到 RTU 填好 `COM7 / 19200`，切回 TCP 还是原来的
  `192.168.1.50:5021`，不用重填。两套都存进工程文件，所以工程本身就能"保存为 RTU 或 TCP"；
- 支持**新建 / 复制 / 删除通道**。删除时若通道上还挂着设备会先提醒（设备会保留但采集不到）；
  改通道名时挂在它下面的设备会**自动跟着搬**，不会因为改名而"掉线"；
- 旧版本建的工程（只有一套参数）打开时会自动把当前这套归到当前链路名下，不丢配置。

## 九、保存与导出

「保存」按用途拆开，各留各的格式，互不影响：

| 动作 | 存什么 | 格式 | 入口 |
|---|---|---|---|
| **保存工程** | 工程到当前位置 | 沿用工程当前格式 | 工具栏「保存工程」 |
| **保存整个工程…** | 工程定义 + 参数表 + 历史库 | 工程目录 / `.iprj` 单文件包 | 工具栏「保存为…」 |
| **保存参数设置…** | 只有点位定义（地址/类型/字序/报警/位定义/命令…） | CSV / TXT / JSON | 工具栏「保存为…」或「设备与点位」页 |
| **导入参数表…** | 读回点位定义 | 按扩展名自动识别（CSV / JSON） | 同上 |
| **导出参数表模板** | 带表头与示例行的空表 | CSV | 同上 |

### 参数表的三种格式

| 格式 | 特点 | 能否导入 |
|---|---|---|
| **CSV 参数表**（默认） | 带 UTF-8 BOM，Excel 双击打开不乱码，可直接编辑 | 能 |
| **TXT 对齐文本** | 制表符对齐（中文按两字宽），适合贴进工单、邮件或打印 | 只导出 |
| **JSON 结构化** | 含完整点位定义，适合做版本管理、程序读取与 diff | 能 |

JSON 的读回刻意**复用 CSV 那套逐行校验**（把行喂给同一段代码），
所以两种格式导入后的结果逐字段一致 —— 有测试专门比对这一点。

### 扩展一种保存格式

在 `icomm/core/writers.py` 里继承 `ParameterWriter`（参数表）或 `ProjectWriter`（整个工程），
用 `register_parameter_writer` / `register_project_writer` 注册即可。保存对话框的格式下拉框、
文件过滤器、扩展名追加全部由注册表生成，**不用改任何界面代码**。
注册顺序就是下拉框顺序，第一个是默认格式。

## 十、按键控制小窗口

现场常见的用法是"一边盯趋势一边按按键启停设备"，模态对话框要关掉才能继续看，
很碍事。所以控制面板做成**非模态浮动窗口**，点完不消失，还能同时开好几个
（一台设备的、若干单点位的）。

两个入口，工具栏「控制台」都能调出：

- **设备的控制台** —— 一台设备一个面板，把该设备上"按一下就动作"的点位做成按键组。
  从设备详情页的「调出控制台」、工具栏「控制台」菜单打开。
- **单点位的按键面板** —— 就一个点位。在点位卡片上**右键 →「调出按键控制小窗口」**，
  或从工具栏「控制台」的单点位列表里选。

### 按键从哪来

全部来自**参数表**，所以改按钮、加按钮都不用改代码：

| 参数表里的列 | 面板上的表现 |
|---|---|
| **命令**（如 `0x04:停机,0x20:启动,0x80:复位`） | 一排按键，点一下就把对应值写下去 |
| **位定义** + 可写（如 `0:软停机方式,1:直接停机方式`） | 每个位一个按键，点一下**翻转该位**后再写入（其它位保持不变） |
| **位定义** + 只读（如运行状态字） | 面板底部显示位状态一览，置位的高亮 |
| 都没有但可写 | 给「取当前值 ± 步长」这类常用操作键，面板里就不塞键盘了 |

### 为什么默认只展开「命令」点位

带位定义的可写点位往往是**配置掩码**（比如 27 位的保护使能），
一次展开就是上百个按键，面板会彻底没法用。所以：

- **默认只列「命令」点位**（那才是真正"按一下让设备动"的键）；
- 需要时点面板上的 **「＋ 添加点位」**自己挑，选过的记在软件设置里，下次自动带上；
- 一台设备一个命令点位都没有时，退化成列前 3 个位域点位，免得面板空白。

面板底部实时显示该点位的持续发送状态（每几毫秒写什么、已发多少次、最近错误），
可以直接「停止发送」；「更多…」打开完整参数对话框。

> 浮动面板（`Qt.Tool` 窗口）会阻止进程退出，所以关主窗口时会一并关掉它们。

## 十一、点位操作：双击改参数、右键单发 / 持续发送

程序里**任意**点位控件都支持 —— 运行监视页的数值卡 / 仪表 / 指示灯 / 波形卡，
以及设备详情页的点位行。

### 双击 = 打开点位参数对话框

- 显示点号、寄存器区与地址、数据类型、字序、缩放偏移、当前值与质量；
- **可写点位**：输入新值后点「单发写入」写一次；
- **命令点位**（如控制字）：直接给命令按钮，点一下写对应命令码 ——
  控制字是"写命令码"语义，手输数字容易写错，所以不提供数字框；
- **位掩码点位**（如功能配置字）：按位勾选，「应用位设置」把组合值写下去，
  也可以按周期持续下发；
- **只读点位**：不出现写入控件，但位状态照样能看；
- 底部实时显示持续发送进度（每几毫秒写什么值、已发多少次、最近错误），可直接停止。

### 右键 = 快捷菜单

```
有功功率给定 （储能变流器PCS.有功功率给定）
──────────────────────────────
单发写入…                        ← 打开对话框写一次
持续发送…                        ← 打开对话框，填周期后开始周期写值
（已在发送时改为 → 暂停持续发送 / 恢复持续发送 / 停止持续发送（发送中，每 200 ms））
──────────────────────────────
添加到示波器                     ← 任何点位都能加，不限于标了「示波器=是」的
写值限幅…（当前 0 ~ 750 V）       ← 超出范围的值先夹到边界再下发
显示小数位数…（当前 1 位）        ← 只改显示
用这个变量做触发条件…             ← 打开截屏辅助并把这个点位预选好
──────────────────────────────
编辑点位定义…                    ← 跳到「设备与点位」页并选中该点位
```

### 单发 与 持续发送

- **单发**：写一次并等设备回响应（超时时间在设置里配），结果进状态栏与通信日志；
- **持续发送**：按周期反复写同一个值，**不等响应、不阻塞采集**，
  发包计数与失败次数在对话框和「持续发送」面板里实时可见。

持续发送有两条安全约定：

1. **不会自动开始**。工程会记住配置，但打开工程、重启采集都不会自己开跑；
   必须在点位上双击 / 右键，或到工具栏「持续发送」面板手动启动；
2. 默认**开始前二次确认**（可在设置里关掉），会提示写什么值、多久一次、大约每秒几次。

工具栏「持续发送」面板集中管理：列出正在发的（发送中 / 已暂停）与工程里记着但没在发的配置，
可批量启动、暂停、恢复、停止。

> 周期精度受通道轮询节奏限制：周期设得比轮询周期还短时，就按轮询周期发
> （Modbus 一条链路上本来也只能串行发帧）。别指望拿它做高频激励。

### 通道的 RTU 与 TCP 参数各记一套

现场调试常要在 RTU（插串口）与 TCP（接网关/仿真器）之间来回切。
通道的每一种链路**各自记住自己的连接参数**：切到 RTU 是 `COM7 / 19200`，
切回 TCP 还是原来的 `192.168.1.50:5021`，不用重填。

两套参数都进工程文件，所以工程本身就能"保存为 RTU 或 TCP"，交给同事也不会丢配置。
旧版本建的工程（只有一套参数）打开时会自动把当前这套归到当前链路名下，不丢。

## 十二、工具集

工具栏「**工具**」菜单里的东西全部来自一张**注册表**，菜单分组、排序、快捷键都由它生成，
界面代码里不出现任何具体工具名。

| 分组 | 工具 | 做什么 |
|---|---|---|
| Modbus | Modbus 报文与 CRC | 手搓/解析 RTU·TCP 报文，自动算 CRC，逐字段说明 |
| 工程 | 变量搜索 | 模糊搜点号/显示名/地址/分组/说明，并回答"**这个变量出现在哪些页面**" |
| 工程 | 记事本 | 随工程保存的备注（谁换过什么、参数为什么这么设） |
| 自动化 | 截屏辅助 | 某个通道达到某个值时自动截屏存盘 |
| 自动化 | 数据记录 | 按设定间隔把指定量记成表格，起始/结束都可用变量触发，可导出 CSV |
| 自动化 | 故障录波 | 报警/自选变量触发时留下触发**前后**各一段波形（默认各 1s），进录波表也可导 CSV |
| 自动化 | 录音 | 同一套触发条件录音（系统自带 winmm），录够时长自动停 |
| 自动化 | 计时器与定时赋值 | 状态栏时钟 + 掐表打时刻标记；到第 N 秒 / 每 N 秒 / 变量触发时给点位写值 |
| 观察 | 示波器小窗口 | 置顶小窗只看波形，能加任何点位（不限于参数表里标了「示波器」的） |
| 工程 | 主回路图编辑 | 电气图元调色板 + 拖动摆位 + 连线 + 绑定实时值 + 点击跳转 |
| 计算 | 分析工具 | 伯德图 / 锁相 / 功率因数功率角 / 三相向量 |
| 计算 | 程序员计算器 | 进制转换、浮点转换、按位勾选 |
| 通信 | TCP 连接测试 | 真连一次并按结果给排查建议（区分"被拒绝/超时/解析失败"） |

### 自己加一个工具

三步，不用改界面代码：

```python
# 1) 新建 icomm/ui/tools/my_tool.py
from .base import ToolContext, WindowTool, register_tool


class MyToolWindow(QWidget):
    def __init__(self, context: ToolContext, parent=None):
        super().__init__(parent or context.window)
        self.context = context          # 工程、实时值、写值、日志都从这里拿


@register_tool                          # 2) 装饰器注册（装饰类即可，框架会实例化）
class MyTool(WindowTool):               # 对话框类工具用 DialogTool，实现 build()
    name = "我的工具"                    #    模态用 DialogTool，浮动窗口用 WindowTool
    group = "工程"                       # 菜单分组
    order = 50                           # 组内排序
    description = "一句话说明"

    def build(self, context: ToolContext):
        return MyToolWindow(context)
```

```python
# 3) icomm/ui/tools/__init__.py 里加一行 import，让它被加载到
from .my_tool import MyTool  # noqa: F401
```

工具**不直接依赖 MainWindow**，只通过 `ToolContext` 拿能力：`project` / `tag_of()` 取实时值 /
`write()` 写值 / `log()` 写日志 / `services["automation"]` 拿自动化核心 /
`add_to_scope()` / `set_write_limit()` / `reveal_point()` / `save_settings()` …
这样主窗口怎么改都不会把工具弄坏，工具也能单独测。

## 十三、自动化：满足条件就做点什么

截屏、数据记录、录音、故障录波、定时赋值……本质都是同一个模式：
**盯一个变量 → 满足条件 → 做一件事**。所以它们共用 `icomm/core/automation.py`：

```
Trigger（条件）                  Task（任务）                AutomationService（调度）
├─ 监视点位 / 比较方式           ├─ 动作 action              ├─ tick(实时值快照)
├─ 阈值 或 bit 序号              ├─ 启用 / 次数上限           ├─ 手动触发
├─ 触发方式：手动/电平/上升沿/下降沿 ├─ 已触发次数 / 最近错误    └─ 任务一览面板
├─ 连续次数（去抖）              └─ 状态文本
└─ 冷却时间
```

- **比较方式**：`>` `>=` `<` `<=` `==` `!=` 、**变化**、**位为 1**、**位为 0**（后三种不用填阈值）；
- **连续次数**：要连续满足 N 次才算触发，用来滤掉毛刺（`hold_count`）；
- **冷却时间**：触发后这段时间内不再重复触发，避免刷屏/刷文件；
- **次数上限**：到数自动停（例如"最多截 20 张"），0 = 不限。

调度跑在**界面线程**（由主窗口的 300 ms 定时器驱动），所以动作可以安全地操作界面；
耗时动作自己在 `Task.action` 里丢线程。

工具栏「**自动化**」按钮打开任务一览：看有哪些任务在跑、各触发过几次、最近一次何时，
可以手动触发、启停或删除。集中一处的好处是现场排查"到底有哪些自动化在互相打架"时一眼能看到。

> 想加新的自动化功能：不用动调度，写个 `Task` 里的 `action` 即可；
> 触发条件的界面控件用 `icomm/ui/tools/variable_trigger.py` 里的
> `build_trigger_fields()` / `read_trigger_fields()`，界面风格与去抖参数自动一致。
>
> ⚠ 这些枚举（`Compare` / `TriggerMode` / `StepMode`）是 `str, Enum`，
> PySide6 会把它们存进 `QComboBox` 的 itemData 时**退化成普通字符串**。
> 从下拉框取值一定要过一遍 `variable_trigger.as_enum()`，
> 否则界面显示"下降沿 / 变量触发"，实际按默认值判断 —— 不报错但行为错。

### 计时器与定时赋值

现场对时间和"按时间动作"用得很多，所以在工具里单独做了一个：

- **时钟**：状态栏常驻当前时间，工具窗口里是大号时、分、秒 + 日期；
- **秒表**：开始 / 暂停 / 继续 / 清零，还能随时按「打时刻标记」记下当前计数值
  （"启动到故障用了 1.7 秒"这种结论，看波形是量不准的）；
- **定时赋值**：加一条动作，选「第 N 秒一次」「每 N 秒一次」或「变量触发」，
  到点就用引擎给点位写值（阶跃响应、周期激励这类试验）。表里能看每条执行过几次。

计时用的是 `time.monotonic()`，所以现场调系统时间不会把计时搞乱；
判断用的是"区间"而不是"等于"，界面卡一下也不会把那一秒漏掉
（每 N 秒的模式跨了多拍会补齐，但一次最多补 10 拍，避免卡死后猛写设备）。

变量触发的动作交给自动化核心，所以边沿、去抖、冷却这些参数自动就有。
**关掉工具窗口会把这些任务一起摘掉** —— 没人看着还在往设备写值更危险。

### 故障录波

现场最需要的是"抓到那一瞬间"：越限往往只有几毫秒到几秒，等看到报警再去点录波，
前面那段已经过去了。所以故障录波**一直在往回记**（环形缓冲），一触发就把
「触发前 pre 秒」的快照 + 「触发后 post 秒」继续采完拼成一段落盘（默认各 1 秒，可改）。

- **标量点位**按采集节奏采样，采样间隔按实际节奏算出来给示波器用；
- **数组/块点位**（DSP 波形缓冲区）按帧整帧保留，跨过触发时刻的那一帧整帧留下 ——
  触发前的数据通常就在那一帧里；
- 录到的波形直接进**现有的录波表**，所以能用「示波器」页的录波回放看，不用另做查看器；
- 同时可选导出 CSV（表头写清触发原因、触发时间、前后时长、每路采样间隔），方便发给别人；
- 一条记录最长录多久可设（默认 60s），防止没人看着把内存吃满。

### 录音

继电器动作声、放电声、风机异响，事后翻录音比翻曲线直观。所以录音和录波同一套路子：
变量触发开录、录够时长自动停，也可以手动录一段。

实现上用 **Windows 自带的 winmm**（`ctypes` 直接调 `waveIn*`），**不引入任何第三方依赖**。
两个工程上的讲究：

- 音频线程的回调里**只做"抄数据 + 归还缓冲区"**，写盘交给后台线程 ——
  在音频回调里写文件一旦磁盘卡顿就会丢采样；
- 收尾时回填 WAV 头，所以即使中途被杀掉，文件里已经录到的数据仍然能用
  （用 Audacity 之类"导入原始数据"能救回来）。

没有录音设备（或不是 Windows）时，工具会明确说出原因，并退化成"什么都不录"的替身，
界面照常能开、能配置。

> 踩过的坑：回调里把 `WAVEHDR.dwFlags` 整个清零会抹掉驱动自己记的 `WHDR_PREPARED`，
> 之后 `waveInAddBuffer` 返回 `WAVERR_UNPREPARED(34)` —— 现象是**永远只能录到 1 秒**
> （正好是第一批 4 个缓冲区）。只清 `WHDR_DONE` 才对。

### 主回路图编辑

主页那张主回路图以前只能改工程文件，现在「工具 → 主回路图编辑」里直接编：

- 左边是**电气图元调色板**（按电源/开关电器/变换与滤波/母线/负载/测量与控制分类），

### 分析工具

## 十四、写值限幅与显示小数位数

### 写值限幅（安全相关）

现场很实际的一件事：给定值不许超出某个范围。上位机手滑把 700 打成 70000，
下位机若没保护就可能炸设备。

- 入口：任意可写点位**右键 →「写值限幅…」**，或在参数表里填「写值下限 / 写值上限」；
- 上下限**留空即那侧不限**；下限比上限大时按"不设限"处理（不会把点位锁死）；
- 夹紧发生在**模型层**（`PointDef.clamp_write`），引擎的**单发**与**持续发送**
  两条写值路径都会调用 —— 不会出现"对话框里限住了、周期发送绕过去"的情况；
- 被夹紧时写一条日志（可在对话框里关掉提示），日志里有原始值与实际下发值；
- 限幅随工程保存进参数表（「写值下限 / 写值上限 / 限幅提示」三列），
  换句话说**换台电脑打开工程，保护还在**。

> 这只防手滑，不是安全联锁。真正的联锁必须放在 PLC/DSP 侧。

### 显示小数位数

右键「显示小数位数…」（0~6 位）。**只影响显示**，不动设备里的值、不改缩放偏移，
也不影响历史库里存的数据。

## 十七、打包为免安装程序

```bash
pip install pyinstaller
pyinstaller --noconfirm VVPhmi.spec
```

产物在 `dist/VVPhmi/`（**实测 79 MB / 171 个文件**），整个目录拷到工控机双击 `VVPhmi.exe` 即可运行，
目标机器无需装 Python。当前只针对 **Windows 11 x64** 打包与验证。
配置见 [VVPhmi.spec](./VVPhmi.spec)，要点：

- 版本号只在 `icomm/__init__.py` 里写一次，spec 读出来写进 exe 的文件属性
  （资源管理器「属性 → 详细信息」能看到）与「关于」对话框；
- `icomm` / `tools` 是源码包，会被打进 PYZ，**不要**用 `--add-data` 当数据文件拷；
- `tools.modbus_sim` 是在函数内部 import 的（内置仿真器按钮），已声明为 hiddenimport；
- **只靠 `excludes` 挡不住 Qt 的二进制依赖**：PySide6 hook 会顺着插件依赖把
  `Qt6Qml/Qt6Quick/Qt6Pdf/opengl32sw` 等约 37 MB 无用 DLL 一并收进来，
  spec 里在 `Analysis` 之后按文件名过滤（本程序纯 QPainter 光栅绘图，不用 OpenGL），体积 115 MB → 79 MB；
- 未加壳（`upx=False`）—— 工业现场常带杀毒软件，加壳容易被误报。

运行时的**工程**放在 exe 同级的 `../VVPproject`（软件目录旁边，见文首），
软件设置放在 exe 同级的 `settings.json`；
从快捷方式、计划任务启动都能正确定位（用的是 exe 自己的路径，不是当前工作目录）。

打包完可顺手做个发布包（**要排掉 `settings.json`** —— 那是本机偏好，里面记着你这台机器的工程仓库路径，

## 十八、已知限制

- 标量历史为「变化即存 + 周期兜底」，超高频点位建议先设死区，避免库表膨胀；
- 录波按段存整块 float32，勾选「录波」前请估算数据量（200 点/秒 ≈ 0.8 MB/小时）；
- 趋势图数据驻留内存（每曲线默认上限 6000 点），长跨度回放依赖数据库查询；
- **没有波形缓冲区时按瞬时值画趋势**：每个采集周期只取一个点，横轴密度由设备的轮询周期决定。
  按 200ms 采样去画 50Hz 会严重混叠（画出来好看但完全是错的），
  要看真实波形必须让 DSP 提供数组/块点位；
- 示波器一次只显示**一段**录波，多段叠加对比尚未实现；
- 尚无用户权限体系，任何能打开程序的人都能改参数表、写点位，请勿直接暴露在公网；
- 写值不做联锁校验（写值限幅只防手滑），安全联锁必须放在 PLC/DSP 侧实现；
- **持续发送既没有联锁也没有速率保护**，按下去就会一直往设备写，
  开始前请再确认一次点位与写入值（设置里可保留默认的二次确认）；
- 持续发送的周期受通道轮询节奏限制，做不到比轮询更快；
- **控制台按钮同样没有联锁**，尤其"按位翻转"类按键是读当前值再写回去，
  如果设备侧同时也在改这个寄存器，可能覆盖掉对方的改动；关键联锁请放 PLC/DSP 侧；
- 界面外观的实时预览会重建页面（防抖 250ms），点位很多时调字号可能略有卡顿；
- 自动化任务的触发判断跑在**界面线程**（300 ms 一次），所以动作必须轻；
  耗时动作要自己在任务里丢线程。触发的最快响应时间也就是这几百毫秒；
- 「截屏辅助」「数据记录」「故障录波」「录音」这类工具是**窗口关掉就停**的
  （否则没人看着还在写盘/录音更糟），想长期跑就别关那个窗口；
- 数据记录把行留在内存里（表格只显示前 5000 行），超长时间记录请配合「最多记录 N 行」或导出后清空；
- 故障录波按配置的点位往回记（环形缓冲），**没勾的点位不记**；缓冲区大小与"触发前时长"成正比，
  点位多、前时长又设得很长时内存占用会上去（有上限保护）；
- 录音走系统默认录音设备（不能在一个窗口里同时选不同设备）；设备被别的程序独占时会打不开并说明原因；
- 分析工具的锁相用的是过零法（对偏置和畸变更皮实、结果能人工核对），
  不是完整的三相 PLL 闭环，快速变频场合只作参考；
- 伯德图是理想 R/L/C 的解析传递函数，不含磁芯饱和、开关频率纹波、死区等实际因素；
- 写值限幅只是**防手滑**：它按点位夹紧，不了解工艺联锁（比如"必须先充电才能启动"），
  这类逻辑仍然必须在 PLC/DSP 侧实现；
- 工具栏按钮较多，窗口最小宽度约 **1000 逻辑像素**（由布局决定）：1280×720 及以上都能放下。
  以前页面里的长文字会把最小宽度顶到 2800 像素、在小屏上窗口宽过屏幕，
  现在这些文字统一用会省略/折行的标签（见 `icomm/ui/widgets.py` 的 `ElidedLabel`），
  窗口还能记住上次的大小与位置（见 [第八节 设置](#八设置)）；
- 软件设置文件与工程文件都是纯文本，手工改坏只会回落默认值，但建议改前备份；
- **只针对 Windows 11 x64 打包与验证**：录音用 winmm（Windows 专有），
  串口按 `COMx` 命名，图标/文件属性按 Windows 约定；其它平台目前只能跑源码。

## 十九、版本管理与发布

版本号只在 [icomm/\_\_init\_\_.py](icomm/__init__.py) 的 `__version__` 里写一次，
界面「关于」对话框与打包出来的 exe 文件属性都取这个值。更新内容记在 [CHANGELOG.md](CHANGELOG.md)。

[.github/workflows/tests.yml](.github/workflows/tests.yml) 会在推送 main / 提 PR 时自动
跑一遍语法检查 + 全部测试，并试着打包一次 exe（校验文件属性里的版本号），产物留档 14 天。
界面探针要真开窗口、真录音、真截图，**只在本地跑**，不进 CI。

发布一个版本的流程：

```bash
# 1) 改版本号（icomm/__init__.py）+ 在 CHANGELOG.md 顶部加一节
# 2) 跑测试与界面自检
python -m unittest discover -s tests -t .
python tools/probe_tools.py 输出目录
# 3) 打包（版本号会自动写进 exe 文件属性）
pyinstaller --noconfirm --clean VVPhmi.spec
# 4) 做发布包
Compress-Archive -Path dist/VVPhmi/* -DestinationPath VVPhmi-1.0.0-win11-x64.zip
# 5) 提交并打标签
git commit -am "release: v1.0.0"
git tag -a v1.0.0 -m "VVPhmi v1.0.0"
git push && git push --tags
```

发布说明的写法（标题 + 一段话说清"给谁用、能干什么" + 变更明细 + 已知限制）：

| 项目 | 内容 |
|---|---|
| 版本号 | `1.0.0` |
| 标签 | `v1.0.0` |
| Release 标题 | VVPhmi v1.0.2 — 默认 DeepSeek 配色，工程目录名统一英文 |
| 发布包 | `VVPhmi-1.0.0-win11-x64.zip`（解压即用，无需装 Python） |
| 说明 | 见 [CHANGELOG.md](CHANGELOG.md) 的 v1.0.0 一节 |

### 工程文件格式版本

`project.json` 里的 `version` 是**工程格式版本**（`project_store.FORMAT_VERSION`），
与软件版本分开走：软件升级加了新字段时，老工程照样能打开（缺的字段取默认值），
所以小版本升级不会要求用户重建工程。
